# @meumouse.com/headpress

## 0.1.1

### Patch Changes

- 9eee226: First release built and staged by CI, with an npm provenance attestation. No API changes.

## 0.1.0

### Minor Changes

- 40475c1: Accounts: `hp.auth` (password, one-time codes by WhatsApp or e-mail, Google, password reset, restore, logout) storing tokens and the customer's Cart-Token; `bffSession()` for browsers whose refresh token lives in an httpOnly cookie (cross-tab locks and broadcasts, a retry after concurrent rotations); `hp.customer` (profile, password change with token rotation, orders as `Money`, downloads, login phone, e-mail verification, Google link, wishlist, addresses, saved payment methods, own reviews); `hp.reviews` (lists, summaries, media, eligibility, votes with a guest voter id, submissions and uploads). **Breaking:** `@meumouse.com/headpress/next` is now safe to import anywhere; `createRevalidateRoute()` and `requestCartToken()` moved to the new `@meumouse.com/headpress/next/server`, which also has `createAuthHandler()`.
- b3de1e1: Analytics and consent: the `@meumouse.com/headpress/analytics` entry with versioned cookie consent and Google Consent Mode v2, typed GA4-style events and item helpers from `Product`/`CartItem`, a consent-gated tracker with GA4, Meta Pixel and Pinterest providers (`providersFromConfig()`), Headpress's Conversions API relay, `purchaseEventId()` as the single source of `purchase_<id>`, `trackPurchase()` (once per order), browser click ids, order attribution for checkout, abandoned-cart capture that requires an explicit marketing choice, and cart recovery links.
- ed8e65f: Catalog, cart, search and content: `hp.catalog` (Store API products with `Money`, stock and quantity rules, storefront paths and the server's price preview; variations, facets, categories, tags, attributes), `hp.cart` (Cart-Token bootstrap and renewal, carts carried by error answers, `subscribe()`), `hp.search` (suggestions, result pages with the `X-Headpress-*` headers, popular searches, the analytics beacon, `highlightSegments()`), `hp.content` (content by path, menus, previews) and `createRecentlyViewed()`. `requestCartToken()` in `/next` reads the shopper's Cart-Token from the request cookies. HTML entity decoding now covers Latin-1 names.
- 446d24d: Checkout and payments: `hp.checkout` (payment methods with the server's kind, installments and discount rule — never guessed; placing orders with `extensions.headpress` built from plain options; `retryPayment()` without a new order; `quoteSplit()`, `shippingQuote()` and `installments()` from the server), `hp.payments` (order ledgers, balance payments, payment links), `paymentInstructions()` for Pix codes and bank slips across gateways, payment adapters (`definePaymentAdapter()`, `resolvePaymentData()`), and the `@meumouse.com/headpress/br` entry (CPF/CNPJ, CEP with ViaCEP, phones, dates, Brazilian Market fields). Split quotes, shipping quotes and price previews need Headpress 1.3.
- d1d9963: Controllers and React: `@meumouse.com/headpress/controllers` (framework-agnostic cart, search box, one-time code sign-in, review form, split builder, shipping quote and Brazilian address form, all `{ getState, subscribe, actions }` with errors kept in state) and `@meumouse.com/headpress/react` (`HeadpressProvider`, `useCart`, `useSearchBox`, `useOtpFlow`, `useReviewForm`, `useSplitBuilder`, `useShippingQuote`, `useAddressForm`, `useStoreConfig`, `useCapability`, `useSignedIn`, `useCustomer`, `useFormatMoney`, `useFormatError`). `hp.auth.restore()` no longer asks the server for guests.
- a0375c4: First release of the core: `createHeadpress()` with the request transport (publishable key, Cart-Token, customer sessions with a shared refresh, captcha, module checks, timeouts), the store config with ETag revalidation and stale fallback, capabilities, the route map (`expandRoute`, `matchRoute`), typed errors with `pt-BR`, `en` and `es` texts, `Money`, plugins, and the `/server` entry (secret key, forwarded shopper IP, `clientIp()`). Requires Headpress 1.2 or later.
- d28df5c: Headpress 1.3 contract: the price preview is read from `extensions.headpress.installments.price_preview` (search results carry it too, as `prices.preview`), `config.commerce.policies` (free-shipping threshold, handling and transit days, return window, minimum order) is typed, `store.headpress_version` is read and a warning fires below `MIN_HEADPRESS_VERSION` (`compareVersions()` is exported). `contract-pull` reads `wp headpress contract export` output, including `routes.json`.
- 0d69fc0: SEO, webhooks, server cache and Next.js: `hp.seo` (heads, redirect rules, sitemaps) with `resolveRedirect()` (Rank Math semantics), `createRedirectResolver()` and sitemap XML renderers; `@meumouse.com/headpress/webhooks` (signature verification with Web Crypto, delivery de-duplication, revalidation plans, a Fetch API handler); `swr()`, `memoryCache()` and `redisCache()` in `/server`; and `@meumouse.com/headpress/next` with the `nextCache()` plugin, `createRevalidateRoute()`, `toNextMetadata()`/`seoMetadata()`, `jsonLdScripts()`, `redirectResponse()` and `xmlResponse()`. Requests take `cacheTags` and `revalidate` for framework caches.
- f6c04f2: Testing helpers: `@meumouse.com/headpress/testing` with `mockHeadpress()` (a fake WordPress REST API with routes like `"POST /wc/store/v1/cart/add-item"` and `:params`, answering `rest_no_route` otherwise), `json()`, `wpError()` and realistic `fixtures` (store config, product, cart, cart item).

### Patch Changes

- eeaea9a: Fixes found while moving the first store onto the SDK: `createServerHeadpress({ clientIp })` forwards the shopper's IP on every call of a per-request client (resources and plugins included); home SEO heads carry the `path:/` tag and `seo.head()` accepts extra `cacheTags`; `redisCache({ clientKeyPrefix })` deletes by pattern through an ioredis `keyPrefix`; `nextCache()` drops `If-None-Match` from tagged reads so the Next.js Data Cache keeps one entry per URL. The README lists the codes the SDK raises itself.
- e4cede1: Fixes found while building the starter: `createConsent().get()` returns the same object until the decision changes (snapshot readers such as `useSyncExternalStore` no longer loop); server error messages are HTML-decoded; catalog reads wait for the store config so storefront paths are never null on the first read; cart lines carry a storefront `path`; `routes.match()` reads query tokens (`order_received`'s `order_id` and `order_key`); `bffSession()` opens its BroadcastChannel only in browsers; `useCart()` fetches on mount only when a Cart-Token exists (option `load`); the analytics item helpers' results fit `track()` without a spread.
